# Factsheet: PISCATOR at a glance

The factsheet summarises all abbreviations and rules on one page. You can use it for reference or give it to a language model so that it proposes a PISCATOR statement for a research project.

## Notation

```
PISCATOR (role): P(…)?, I(…)?, S(…)?, C?, A: models, languages, period, T(…), O(…)?, R(…)?
```

- As in CLEAR, suffixes precede the number: P(s, n)3, I(CH)2, S(p)2, O(or, sy)0, R(v)2.
- For P, I, S, C and R, give the highest level reached; for T and the forms in O, list all applicable codes.
- X means: does not occur in this research (SX, PX, IX, TX, OX).
- If work steps differ considerably, each gets a line of its own: “PISCATOR (project team, training)”.

## Abbreviations

| Abbreviation | Meaning |
|---|---|
| **P** | **Privacy – personal reference of the data an AI processed** |
| P0 | No personal reference. |
| P1 | Anonymised. |
| P2 | Pseudonymised: re-attributable by means of a key, even if third parties hold it. |
| P3 | Identifiable. |
| (s) | Sensitive personal data, according to Art. 5(c) Swiss FADP and Art. 9 GDPR. |
| (p) | Data published, openly accessible. |
| (r) | Restricted access: on request or with controlled access. |
| (e) | Publication planned, for example after an embargo. |
| (n) | Data not published. |
| **I** | **Infrastructure – where the AI with access to the data ran** |
| I0 | Local, on one’s own computer. |
| I1 | Protected infrastructure of one’s own institution. |
| I2 | External service with a data processing agreement. |
| I3 | External service with general terms of use only. |
| (CH) … | Country of server location, for example (CH), (DE), (EU), (US). |
| **S** | **Script – AI in programming** |
| S0 | Without AI. |
| S1 | Assistance: completion, debugging, explanation. |
| S2 | Parts generated. |
| S3 | Largely generated, read and revised by the human. |
| S4 | Fully generated, without a human reading the code. |
| (p) (r) (e) (n) | Availability of code and prompts, as for P. |
| **C** | **Conception – research question, hypotheses, design, instruments** |
| C0 | Exclusively human. |
| C1 | AI as a discussion partner. |
| C2 | Individual parts worked out by the AI. |
| C3 | Comprehensively generated by the AI. |
| **A** | **Attribution – declaration:** models and tools with version, provider and type of use (applied, adapted, trained), programming languages, period. |
| **T** | **Transformation – what the AI did with the data** |
| T0 | Collection and processing without AI. |
| (co) | Collection: interviews, surveys, data gathering by AI. |
| (ts) | Transcription. |
| (oc) | Text and handwriting recognition. |
| (t) | Translation, as L(t) in CLEAR. |
| (ps) | Pseudonymisation: names and identifiers replaced or removed. |
| (cl) | Cleaning. |
| (im) | Imputation of missing values. |
| (li) | Linkage of datasets. |
| (ex) | Extraction of information from documents. |
| (su) | Summarisation with which work continues. |
| (an) | Coding, classification, annotation. |
| (mo) | Modelling: the AI produces findings itself. |
| **O** | **Origin – source and form of the data** |
| O0 | Own collection or generation only. |
| O1 | Own collection and reused data. |
| O2 | Reused data only. |
| (or) | Original. |
| (sc) | Scrambled: values swapped, masked or perturbed. |
| (ag) | Aggregated. |
| (sy) | Synthetic. |
| (si) | Simulated or model-generated. |
| (au) | Augmented. |
| **R** | **Responsibility – accountability** |
| R1 | Fully checked and taken responsibility for by the human. |
| R2 | Spot-checked. |
| R3 | Used unchecked, with the risk of having to take responsibility for it nonetheless. |
| (v) | Systematically validated, procedure and figures documented. |

## Prompt for a language model’s self-declaration

A language model can propose a PISCATOR statement. To do so, copy the following text into the chat in which you worked on the project. The model proposes what it can derive from the conversation and asks about the rest. R is always set by you.

```
Please label, according to PISCATOR, how AI was involved in this research project. Base your answer on our conversation so far. Whatever you cannot derive from it with certainty, ask me instead of guessing. This applies above all to P, I and O.

For each axis, give the applicable statement and justify it in one sentence. X means: does not occur in this project.

P – Privacy (personal reference of the data an AI processed): P0 no personal reference · P1 anonymised · P2 pseudonymised · P3 identifiable; suffixes (s) sensitive · (p) published · (r) restricted access · (e) publication planned · (n) not published
I – Infrastructure (where the AI with access to the data ran): I0 local · I1 protected infrastructure of the institution · I2 external service with a data processing agreement · I3 external service with general terms of use only; suffix: country of server location, e.g. (CH)
S – Script (AI in programming): S0 without AI · S1 assistance · S2 parts generated · S3 largely generated, read by the human · S4 fully generated, without reading the code; suffixes (p) (r) (e) (n) for code and prompts
C – Conception (research question, hypotheses, design, instruments): C0 exclusively human · C1 AI as a discussion partner · C2 individual parts worked out by the AI · C3 comprehensively generated by the AI
A – Attribution: models and tools with version, provider and type of use (applied, adapted, trained), programming languages, period
T – Transformation (what the AI did with the data): (co) collection · (ts) transcription · (oc) text recognition · (t) translation · (ps) pseudonymisation · (cl) cleaning · (im) imputation · (li) linkage · (ex) extraction · (su) summarisation · (an) coding · (mo) modelling; T0 without AI
O – Origin: O0 own collection only · O1 own and reused data · O2 reused data only; forms (or) original · (sc) scrambled · (ag) aggregated · (sy) synthetic · (si) simulated · (au) augmented
R – Responsibility: Leave R open. Only the human can make this statement.

Format: PISCATOR (role): P(…)?, I(…)?, S(…)?, C?, A: …, T(…), O(…)?, R?
Suffixes precede the number, for example P(s, n)3 or O(or, sy)0. If work steps differ considerably in personal reference or infrastructure, propose a separate line for each step.
```

## Limits of the self-declaration

A model can only assess what it has seen. With PISCATOR, this is even less than with CLEAR: where data are stored, whether they were pseudonymised and which agreements are in place rarely appear in a chat. The model should therefore ask, and the answers come from you.

A research project also rarely takes place in a single chat. If you used several chats, tools or models, the model can assess only part of it. In that case, make the classification yourself.

Even in the best case, the model’s statement remains a proposal that you check and correct where necessary. Only a human can take on responsibility (R).
